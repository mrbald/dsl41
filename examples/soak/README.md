# Soak — a 200-job capacity estate

A synthetic estate of the size dsl41 is sized for, and the scripts that
measure what the runner does with it. The results are in the deployment
runbook's [capacity and limits](../../docs/deployment-runbook.md#capacity-and-limits)
section.

## The estate

`estate/soak.jil` is generated by `generate.py` from a seed (41). It has 200
jobs on one machine, `soakhost`, whose `max_load: 20` admits 20 runs at once.
The jobs start about 1,000 times a day, each 1 to 5 times:

- 16 boxes of 6 members, with chains and fan-in inside each box. Every box
  starts at 02:00, so the night's batch asks for more than 20 slots and the
  machine queues the rest.
- 43 scheduled jobs and 30 condition jobs: chains, and fan-in over two
  upstream jobs with zero lookbacks.
- 6 jobs that start each hour inside a `run_window`.
- 4 jobs that fail every run, each with a retry job on `f(...)`, and an
  alert job on the one box that fails.

Every command is `sleep N`, `true`, `false` or `sleep N; false`. Every name
is invented. dsl41 does not model `n_retrys` (DL-53), so a retry is a job of
its own. Machine load is checked only for a job with a positive priority
(DL-247), so every command job sets one.

Regenerate it with `uv run python examples/soak/generate.py`. The output is
byte-stable for a seed, and `tests/test_soak_example.py` checks that and the
size.

## The compressed run

`compressed.py` plays the estate under a virtual clock, as `dsl41 rehearse`
does, and writes one JSON line per day. Each job's outcome comes from its
command. Each day also carries a little operator traffic: a forced start,
its exact retry, a hold and its release, and a request id reused for
another command.

Seven days, sealed at every midnight as production would seal (each day is
one engine process; `audit` attests each period):

```sh
uv run python examples/soak/compressed.py sealed --days 7 --root /tmp/soak-sealed --out sealed.jsonl
```

Seven or thirty days in one period, sealed once at the end. It also times
the replay a restart pays at the end of the period:

```sh
uv run python examples/soak/compressed.py period --days 30 --root /tmp/soak-period --out period.jsonl
```

The same days through `dsl41 rehearse --run-root`, in one period:

```sh
uv run python examples/soak/compressed.py scenario --days 7 --root /tmp/soak-7.json
uv run dsl41 rehearse examples/soak/estate/soak.jil --run-root /tmp/soak-rehearse \
    --start 2026-01-05T00:00:00 --hours 168 --scenario /tmp/soak-7.json --format json
```

Each day's line has the wall and CPU time of playing the day, the launches,
failures and queue waits, the most runs live at once, the length of the
oracle trace and of the engine's `drops`, `deduped` and `refusals` lists,
the decision index and the outbox, the open segment's and the whole WAL's
bytes, the resident set, and the time one `trace` and one `status` control
call take in process. The CPU is the engine's decision cost under a virtual
clock with a fake adapter: no processes, no supervisor and no spool. It is
not a real day's CPU. The `seal`, `replay` and `audit` lines carry their
times; seal and replay are timed in process, audit as a command.

## The real-clock soak

`soak.sh` starts `dsl41 run --detached` on the estate with real commands,
and a sampler that writes one line a minute to `samples.jsonl`. After the
given minutes it runs `stop.sh`, which seals the period, audits it, waits
for the commands still running to end, and shuts the supervisor down.

```sh
uv run examples/soak/soak.sh /tmp/soak-24h 1440   # a day
uv run examples/soak/stop.sh /tmp/soak-24h        # to stop it earlier
```

The directory must not exist, and its path must be short: the run root's
unix sockets live in it, and a socket path holds at most 104 bytes on macOS.
The engine, the sampler and the timer outlive the shell that started them.

A sample holds the engine's and the supervisor's resident set, CPU time and
open descriptors, the open period's WAL segment and the whole WAL, the trace
length, the command runs and boxes live, the runs queued, and how long one
`trace` and one `status` call took at the socket. `stop.jsonl` holds the
seal, audit and drain times, and whether the drain saw every command end.
An engine still running two minutes after the seal stops `stop.sh` with
exit 1 before the audit; `ENGINE_EXIT_SECONDS` sets the wait.
